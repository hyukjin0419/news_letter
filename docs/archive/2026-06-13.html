희토류 없이 전기차 모터를 만든다고요? 르노가 12년째 해오고 있었어요

• 전기차 모터의 90%는 희토류 영구자석을 씁니다. 근데 중국이 전 세계 희토류의 85~100%를 생산하고, 자국 소비를 우선시하고 있어요. 공급망 리스크가 얼마나 큰지 감이 오시죠? 르노는 이 문제를 2012년부터 EESM(전기 여자 동기 모터)으로 피해왔어요.
• 영구자석 대신 전류로 자기장을 만드는 권선 회전자(Wound Rotor) 방식을 씁니다. 희토류가 아예 필요 없어요. 캉구 Z.E., 조이(Zoe)를 시작으로 지금까지 여러 모델에 양산 적용 중이에요.
• 2027년 출시 예정인 3세대 E7A 모터는 출력 200kW, 크기 30% 축소, 탄소 발자국 30% 감소, 효율 92%를 목표로 해요. 800V 시스템 아키텍처도 함께 도입될 예정이고요.

💡 오늘의 인사이트

우리가 인프라를 설계할 때 특정 벤더에 종속되면 나중에 얼마나 골치 아픈지 잘 알잖아요. 르노 이야기는 전기차 얘기지만, 사실 공급망 리스크를 기술 선택으로 미리 피한 아키텍처 결정 사례예요. '지금 당장 주류 기술이 아니더라도, 의존성을 줄이는 방향으로 설계한다'는 원칙은 소프트웨어에서도 똑같이 유효해요.

WAVE 02 661 pts · 168 comments

CRISPR이 암세포만 골라서 터뜨린다고요? '치료 불가' 딱지 붙은 암도요

• 전체 암의 절반, 난소암과 췌장암의 70~90%에서 발견되는 p53 종양 억제 유전자 돌연변이. 근데 이 단백질엔 약이 결합할 구조적 틈이 없어서 지금까지 표적 치료제가 단 하나도 없었어요. UC 버클리·UCSF·글래드스톤 연구팀이 이 문제를 완전히 다른 방식으로 접근했어요.
• 돌연변이 단백질을 고치려는 게 아니라, 그 세포 자체를 없애버리는 거예요. CRISPR-Cas12a2가 암세포 특이적 RNA 전사체를 감지하면, 크로마틴을 잘게 부숴 세포를 파괴해요. 바이러스를 막는 미생물의 면역 메커니즘을 그대로 활용한 거예요.
• 이 시스템은 프로그래머블해요. 새로운 돌연변이에 맞게 빠르게 재설계할 수 있어서, 소분자 약물이나 항체 치료제를 새로 개발하는 것보다 훨씬 빠르게 대응할 수 있어요. 다만 큰 효소를 모든 암세포에 전달하는 딜리버리 문제는 아직 풀어야 할 숙제예요.

💡 오늘의 인사이트

기존 방식으로 안 풀리면, 문제 정의 자체를 바꿔보는 거잖아요. '이 버그를 어떻게 고칠까'가 아니라 '이 컴포넌트를 아예 교체하면 어떨까'처럼요. 연구팀이 p53을 고치려는 시도를 포기하고 세포 제거로 방향을 튼 것처럼, 우리도 막힌 문제 앞에서 가끔은 접근법 자체를 갈아엎는 용기가 필요해요.

WAVE 03 107 pts · 49 comments

애플이 C로 짠 폰트 렌더러를 Swift로 다시 썼어요. 성능이 13% 더 빨라졌고요

• TrueType 힌팅 인터프리터는 외부에서 들어오는 폰트 데이터를 처리해요. 신뢰할 수 없는 소스의 입력을 다루는 보안 핵심 컴포넌트인데, 기존 C 구현은 복잡한 제어 흐름과 메모리 관리로 취약점에 노출될 위험이 있었어요. 애플은 이걸 메모리 안전한 Swift로 완전히 다시 썼어요.
• 결과가 놀라워요. 픽셀 단위로 기존 C 구현과 동일한 렌더링을 유지하면서 평균 13% 성능이 향상됐어요. 코드 커버리지 99.7%의 단위 테스트를 작성했고, 프로덕션 코드보다 테스트 코드를 4배 더 많이 썼어요.
• 실세계 검증도 철저했어요. 퍼저로 PDF 파일 1천만 개를 4,200개로 압축해서 2,700만 개의 글리프를 테스트했어요. 소스 코드는 GitHub에 프로덕션 레퍼런스 구현으로 공개돼 있어요.

💡 오늘의 인사이트

레거시 C 코드를 Swift로 바꾸면서 성능까지 올렸다는 게 핵심이 아니에요. 진짜 인상적인 건 테스트 코드가 프로덕션 코드의 4배라는 점이에요. 마이그레이션의 성공 기준을 '동작하는 것'이 아니라 '증명 가능한 동일성'으로 잡은 거잖아요. 다음에 레거시 코드를 손댈 일이 생기면, 얼마나 믿을 수 있는 테스트 망을 먼저 깔아두느냐가 전부예요.
