앱이 서버 없이도 AI를 쓸 수 있다면, 왜 굳이 클라우드를 쓰고 있나요?

• OpenAI나 Anthropic API를 붙이는 게 당연한 흐름처럼 됐지만, 서버가 죽거나 결제가 끊기는 순간 기능 전체가 날아가요. 외부 의존성이 하나 늘 때마다 장애 포인트도 하나씩 늘어나는 거죠.
• 사용자 데이터를 서드파티 AI 서버로 보내는 순간 개인정보 이슈, 컴플라이언스 검토, 데이터 보존 정책까지 따라와요. 기능 하나 붙이려다 법무팀이랑 두 시간 회의하게 되는 그 상황 말이에요.
• Apple의 FoundationModels 프레임워크와 SystemLanguageModel API를 쓰면 요약, 분류, 텍스트 정규화 같은 작업을 기기 안에서 처리할 수 있어요. 네트워크도, 요금도, 속도 제한도 없이요. 기기 안에 Neural Engine이 이미 있는데 클라우드 응답을 기다리고 있었던 거예요.

💡 오늘의 인사이트

클라우드 AI API를 붙이는 게 빠른 것 같지만, 그 순간부터 내 앱의 신뢰성이 남의 서버 상태에 달리게 돼요. 요약이나 분류처럼 '딱 이 정도' 작업이라면, 온디바이스 모델로 충분한지 먼저 따져보는 게 좋아요. 외부 의존성을 줄이는 것 자체가 아키텍처를 단단하게 만드는 일이니까요.

GitHub 별 12개짜리 Rust 라이브러리가 개발자 400만 명을 감염시킨 방법

• 공격은 흔한 피싱으로 시작됐어요. 하드웨어 2FA 키를 탈취당한 메인테이너의 계정이 뚫렸고, left-justify라는 JavaScript 패키지에 악성 postinstall 스크립트가 심겼어요. 이 스크립트는 .npmrc, .pypirc, ~/.cargo/credentials, ~/.gem/credentials를 그대로 빼갔어요.
• 탈취한 자격증명으로 Rust 압축 라이브러리 vulpine-lz4에 악성 코드를 심었는데, 이 라이브러리가 cargo 자체의 간접 의존성이었어요. GitHub 별이 12개인 라이브러리가 npm, PyPI, Cargo 생태계를 동시에 건드린 거죠.
• 악성 코드는 SSH 키 추가, 리버스 셸 설치, 기본 셸 교체까지 했어요. 73시간 동안 약 400만 명의 개발자에게 배포됐고, 보안 리포트는 낮은 우선순위로 분류돼 자동으로 닫혔어요. 결국 관련 없는 암호화폐 채굴 웜이 덮어쓰면서 우연히 패치됐어요.

💡 오늘의 인사이트

내 프로젝트의 package.json이나 Cargo.toml을 열어보면, 직접 추가한 의존성보다 간접 의존성이 훨씬 많아요. 별이 몇 개인지, 다운로드가 얼마나 되는지와 상관없이 그 코드는 내 머신에서 실행돼요. postinstall 스크립트를 허용하는 패키지가 몇 개인지, npm audit이나 cargo audit을 마지막으로 돌린 게 언제인지 오늘 한 번 확인해보는 게 어떨까요.

Qubes OS를 만든 보안 연구자가 7년 만에 블로그를 다시 시작한 이유

• 2009년부터 보안 중심 운영체제 Qubes OS 개발을 이끌었던 연구자가 7년간의 침묵을 깨고 새 블로그를 열었어요. 2006년부터 2018년까지 컴퓨터 시스템과 운영체제 보안을 주제로 글을 써온 사람이에요.
• 새 블로그의 주제는 기술이 아니에요. 합리성과 인간주의, 실용주의와 아름다움, 개인의 자유와 공동체 가치 사이의 긴장감을 탐구하겠다고 했어요.
• 그는 예전엔 진실과 자유를 가장 중요한 가치로 뒀는데, 지금은 그 가치 체계가 훨씬 복잡해졌다고 해요. 오랫동안 기술의 최전선에 있던 사람이 결국 사람에 대한 질문으로 돌아온 거예요.

💡 오늘의 인사이트

코드를 오래 짜다 보면 어느 순간 '이걸 왜 만드는 거지?'라는 질문이 찾아와요. 기술적으로 가장 뛰어난 사람이 결국 사람과 공동체에 대한 이야기로 돌아온다는 게, 저는 꽤 위안이 됐어요. 지금 당장 답이 없어도 괜찮아요. 그 질문을 붙들고 있는 것 자체가 좋은 엔지니어가 되는 과정이니까요.
