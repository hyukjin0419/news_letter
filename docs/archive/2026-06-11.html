AI 보안 모델이 코드 리뷰를 막는다고요? Anthropic Fable 논란 정리

• Anthropic이 사이버보안 특화 모델 Fable을 공개했는데, 키워드 기반 가드레일이 너무 넓게 걸려 있어요. '보안'이나 '취약점' 같은 단어가 들어간 정상적인 코드 리뷰 요청도 막혀버리는 상황이죠.
• 악의적인 사용자는 다른 표현으로 우회할 수 있는데, 정작 선의의 개발자들만 불편을 겪는 아이러니한 구조예요. 보안 전문가들 사이에서 '너무 대충 만든 필터 아니냐'는 비판이 나오는 이유가 여기 있어요.
• 보안 업무에 제한 없이 Claude를 쓰려면 Cyber Verification Program에 별도로 신청해야 해요. 보안 팀이 있는 회사라면 미리 알아두면 좋을 것 같아요.

💡 오늘의 인사이트

키워드 필터링은 구현하기 쉬운 만큼 허점도 많아요. 나쁜 사람은 말을 바꾸면 그만이지만, 착한 사람은 시스템에 막혀서 시간을 낭비하죠. 우리가 서비스에서 입력값을 검증할 때도 비슷한 함정에 빠지기 쉬워요. '이 필터가 진짜 막아야 할 것을 막고 있나, 아니면 그냥 불편함만 만들고 있나' 한 번쯤 돌아볼 만한 사례예요.

파일을 원주율 안에 저장한다고요? 진지한 척하는 농담 같은 프로젝트

• πfs는 파일 데이터를 디스크에 저장하는 대신, 원주율(π)의 자릿수 안에서 해당 데이터가 있는 위치를 찾아 저장하는 파일시스템이에요. 실제 데이터 대신 위치 메타데이터만 보관하는 방식이죠.
• 구현에는 Bailey–Borwein–Plouffe formula와 libfuse를 사용했어요. 400줄짜리 텍스트 파일 하나 저장하는 데 5분이 걸렸다고 하니, 실용성은 논외로 하는 게 맞을 것 같아요.
• 메타데이터를 잃으면 파일을 영영 찾을 수 없고, 전제 자체가 수학적으로 아직 증명되지 않은 추측에 기반해요. GitHub에 올라온 프로토타입이고, 만든 사람도 진지하게 쓰라고 만든 건 아닐 거예요.

💡 오늘의 인사이트

이런 프로젝트가 괜히 좋아요. 쓸모없다는 걸 알면서도 '이게 되네?'라는 순간을 즐기는 거잖아요. 실용적인 것만 만들다 보면 어느 순간 흥미를 잃게 돼요. 가끔은 이렇게 말도 안 되는 아이디어를 끝까지 구현해보는 경험이, 나중에 진짜 문제를 풀 때 의외의 힌트가 되기도 하더라고요.

ZDR 설정해뒀다면 꼭 확인하세요. Anthropic 30일 데이터 보관 정책 변경

• 2026년 6월 9일부터 Mythos급 모델을 사용하는 조직은 프롬프트와 응답이 30일간 보관돼요. 기존에 Zero Data Retention(ZDR) 설정을 쓰던 조직도 예외가 없어요.
• 대상은 Claude Console, Claude Code with ZDR, AWS Bedrock, Google Cloud Agent Platform, Microsoft Foundry 환경이에요. 일반 소비자 플랜인 Free, Pro, Max는 영향 없어요.
• 30일 후 자동 삭제되고, 접근 권한은 엄격히 제한되며 감사 로그도 남아요. 고객 관리 암호화 키 옵션도 있으니, 보안 요건이 까다로운 팀이라면 정책 문서를 꼼꼼히 읽어볼 필요가 있어요.

💡 오늘의 인사이트

ZDR은 '우리 데이터는 절대 안 남긴다'는 전제로 도입한 설정이에요. 그런데 이번 변경은 그 전제를 바꾸는 거라 컴플라이언스 팀 입장에서는 꽤 민감한 이슈예요. 6월 전에 내부 보안 정책이나 고객사 계약서에 데이터 보관 관련 조항이 있는지 미리 확인해두는 게 좋아요. 나중에 '그런 정책이 바뀐 줄 몰랐어요'는 꽤 곤란한 상황을 만들 수 있거든요.
