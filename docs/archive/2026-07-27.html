HyperCard가 돌아왔다, 그것도 MIT 라이선스로

• Decker는 1980년대 HyperCard에서 영감을 받은 오픈소스 인터랙티브 문서 플랫폼이에요. 프레젠테이션, 게임, 픽셀 아트까지 만들 수 있고, 광고도 텔레메트리도 없어요. 진짜로요.
• 자체 스크립팅 언어인 Lil이 내장되어 있는데, Lua와 Q에서 영향을 받았어요. 암묵적 스칼라-벡터 연산과 SQL 스타일 쿼리를 지원해서 생각보다 꽤 쓸 만해요.
• 덱 파일이 줄 단위 텍스트 형식으로 저장돼서 Git이나 SVN으로 버전 관리가 바로 돼요. 헤드리스 실행도 되고 크로스플랫폼 바이너리도 있어서 CI 파이프라인에 끼워 넣기도 어렵지 않아요.

WAVE 02 113 pts · 48 comments

불이 스스로 날씨를 만든다, 개발자가 알아야 할 이유가 있어요

• 프랑스 남서부 산불이 pyrocumulonimbus, 즉 '불 구름'을 만들어냈어요. 지면의 극단적인 열이 상승 기류를 형성해 자체적으로 바람과 번개를 일으키는 기상 시스템이에요. 프랑스에서는 처음 기록된 현상이에요.
• 이 구름이 생기면 불이 여러 방향으로 동시에 번지고, 번개가 새로운 불씨를 만들어요. 소방관들이 '작전 불가' 상태를 선언했을 정도로 기존 대응 방식이 통하지 않아요.
• 해결책은 사흘 이상의 폭우이거나, 불이 자연 장벽인 바다 쪽으로 향하길 기다리는 것뿐이에요. 시스템이 스스로 피드백 루프를 만들어버리면 외부 개입이 사실상 불가능해지는 상황이에요.

WAVE 03 168 pts · 66 comments

"타협 없는 제품"이라는 말은 거짓말이에요

• 모든 디자인 결정은 트레이드오프예요. 어떤 강점을 살리면 반드시 어딘가에서 약점이 생겨요. '타협 없는 제품'이라는 표현은 마케팅 문구일 뿐, 기술적으로는 불가능한 주장이에요.
• 좋은 설계는 '모두를 만족시키는 것'이 아니라 '우리 사용자에게 맞는 트레이드오프를 의도적으로 선택하는 것'이에요. 명확한 약점을 인정하는 제품이 오히려 더 신뢰를 얻어요.
• API 설계, 아키텍처 선택, 라이브러리 선정 모두 마찬가지예요. REST냐 GraphQL이냐, 모놀리식이냐 마이크로서비스냐, 정답은 없고 맥락에 맞는 선택만 있어요.

💡 오늘의 인사이트

코드 리뷰나 기술 결정 회의에서 '이 방식은 이런 약점이 있지만, 우리 상황에서는 이 강점이 더 중요해서 선택했어요'라고 말할 수 있는 사람이 진짜 시니어예요. 근거 없는 자신감보다 명확한 트레이드오프 설명이 팀의 신뢰를 훨씬 빠르게 쌓아줘요. 다음 결정 때 한번 써보세요.
