AI한테 재무 상담 받아봤더니, 질문을 잘 해야 답도 좋더라고요

• MIT 슬론 연구팀이 GPT-5.2, GPT-5.6, Gemini 3 Flash에게 1,000명분의 재무 시뮬레이션을 돌렸어요. 저축 늘리기, 분산 투자, 나이에 맞는 리스크 조절 같은 기본기는 꽤 잘 짚어줬는데, 갑자기 실직하거나 시장이 흔들리는 상황에선 제대로 된 조언을 못 했어요. 현실은 교과서대로 안 흘러가잖아요.
• 포트폴리오 리밸런싱도 문제예요. AI는 '지금 상태'에 답할 뿐, 시간이 지나면서 비중이 틀어지는 걸 알아서 잡아주진 않아요. 우리가 cron job 안 걸어두면 배치가 안 도는 것처럼, AI도 능동적으로 움직이진 않더라고요.
• 그런데 재밌는 게 있어요. 구조화된 프롬프트, 그러니까 나이, 소득, 부채, 목표를 꼼꼼히 넣어서 물어보면 답의 질이 확 달라졌어요. 결국 AI한테도 좋은 input을 줘야 좋은 output이 나오는 거죠. 개발할 때랑 똑같아요.

💡 오늘의 인사이트

미국인 절반이 AI로 재무 상담을 한다는 건, 이미 사람들이 AI를 도구로 쓰기 시작했다는 신호예요. 우리가 만드는 서비스에 AI 어시스턴트를 붙일 때, 사용자가 어떤 정보를 입력하게 유도할지 UX 차원에서 설계하는 게 중요해질 것 같아요. 프롬프트 품질이 곧 서비스 품질이 되는 시대니까요.

WAVE 02 122 pts · 18 comments

문서 쓰다가 막힌 적 있죠? 이 프레임워크 하나면 정리돼요

• Diátaxis는 기술 문서를 네 가지로 나눠요. 튜토리얼, 하우투 가이드, 레퍼런스, 설명 문서. 들어보면 당연한 것 같은데, 실제로 이걸 구분 못 해서 튜토리얼에 레퍼런스를 섞거나, 설명 문서에 따라하기 내용을 넣는 경우가 정말 많아요. 읽는 사람이 원하는 게 뭔지를 먼저 생각하자는 거예요.
• 이 프레임워크가 좋은 이유는 가볍다는 거예요. 특정 도구나 포맷을 강제하지 않아요. README든, GitBook이든, Notion이든 어디에나 적용할 수 있어요. Vonage, Gatsby, Cloudflare 같은 곳도 이미 쓰고 있고요.
• 문서를 어떻게 쓸지뿐만 아니라, 어디에 어떤 문서를 둘지 구조 설계까지 다뤄요. 팀에 새 사람이 왔을 때 문서 보고 헤매는 일, 이 프레임워크로 많이 줄일 수 있어요.

💡 오늘의 인사이트

코드는 잘 짜는데 문서는 늘 미루게 되죠. 저도 그랬어요. 그런데 Diátaxis를 알고 나서 달라진 게 있어요. 지금 이 문서를 읽는 사람이 뭘 원하는지를 먼저 물어보게 됐거든요. 처음 배우려는 건지, 특정 작업을 해결하려는 건지, 그냥 레퍼런스가 필요한 건지. 그 질문 하나만 해도 문서 퀄리티가 달라져요. 팀 위키 정리할 때 한번 써보세요.

WAVE 03 75 pts · 25 comments

30초짜리 영상을 이미지 30장으로 만든다고요? Seedance 2.5 써봤어요

• ByteDance가 만든 Seedance 2.5는 한 번에 30초짜리 오디오 포함 영상을 뽑아줘요. 이미지 최대 30장, 영상 클립 10개, 오디오 클립 10개를 레퍼런스로 넣을 수 있어요. 멀티모달 입력을 이 정도 규모로 받는 건 꽤 드문 일이에요.
• 타임스탬프 단위로 편집 제어가 된다는 게 인상적이에요. 특정 구간의 오디오만 바꾸거나, 영상의 일부 장면만 수정하는 게 가능해요. 그린 스크린, 카메라 앵글 조정, 레퍼런스 기반 편집도 지원해요. BytePlus ModelArk를 통해 API 연동도 준비 중이에요.
• 다만 여러 피사체가 서로 상호작용하는 복잡한 장면에서는 아직 불안정하다고 공식적으로 인정했어요. 물리적으로 자연스럽지 않은 동작이 나올 수 있어요. 프로덕션에 바로 쓰기보다는 프로토타입이나 내부 시안 단계에 써보는 게 현실적이에요.

💡 오늘의 인사이트

영상 생성 모델이 API를 열기 시작하면, 우리 서비스에 영상 콘텐츠를 자동 생성하는 파이프라인을 붙이는 게 멀지 않은 얘기가 돼요. 마케팅 팀이 요청한 배너 영상이나 튜토리얼 클립을 자동화할 수 있는 날이 오는 거죠. 지금 당장 쓰진 않더라도, API 스펙이 어떻게 생겼는지 한번 훑어두면 나중에 빠르게 치고 나갈 수 있어요.
