AI가 쓴 문서, 이제 항공우주 표준으로 다듬을 수 있어요

• 1983년 항공우주 산업에서 만든 ASD-STE100 표준을 LLM 출력에 강제 적용하는 에이전트 스킬이 나왔어요. 문장당 최대 20단어, 능동태, 단순 시제, should/would/may/might 같은 모호한 표현 금지 같은 53개 규칙을 적용해요.
• Claude 6개 모델 기준으로 96번 테스트한 결과, STE 위반이 72.9% 줄었어요. 평균 문장 길이도 11.2단어에서 9.7단어로 짧아졌고, 출력 토큰도 모든 모델에서 감소했어요.
• Claude Code, Cursor, VS Code Copilot, OpenAI Codex, Gemini CLI 등 25개 이상 도구와 호환돼요. npm으로 설치하거나 시스템 프롬프트로 붙여넣기만 하면 바로 쓸 수 있어요.

💡 오늘의 인사이트

런북, 인시던트 리포트, 릴리즈 노트... 팀마다 AI한테 맡기는 문서가 하나씩은 있죠. 근데 AI가 쓴 글은 길고 모호하고, 읽다 보면 '그래서 뭘 하라는 거야' 싶을 때가 많아요. 이 스킬은 그 문제를 항공우주 산업이 수십 년간 다듬어온 방식으로 해결해요. 마케팅 문서엔 안 맞지만, 기술 문서만큼은 한번 적용해볼 만해요. AI 출력을 그대로 붙여넣기 전에, 프롬프트 한 줄 추가하는 것만으로 문서 품질이 달라질 수 있거든요.

GitHub에 스택 PR이 생겼어요. 큰 PR 올리기 무서웠던 분들 주목해요

• GitHub가 스택 PR을 공개 프리뷰로 출시했어요. 큰 변경사항을 작고 리뷰 가능한 PR 여러 개로 나눠서 순서대로 쌓을 수 있어요. 각 PR은 바로 아래 레이어를 타겟으로 해서, 리뷰어들이 서로 다른 레이어를 동시에 검토할 수 있어요.
• 스택 전체를 한 번에 머지할 수도 있고, 개별 레이어만 머지하면 나머지 PR이 자동으로 리베이스되고 타겟이 바뀌어요. 기존 브랜치 보호 규칙, 머지 요건은 그대로 유지돼요.
• gh extension install github/gh-stack으로 GitHub CLI 확장을 설치하거나, github.com, 모바일 앱, GitHub Copilot 같은 코딩 에이전트에서도 바로 쓸 수 있어요.

💡 오늘의 인사이트

솔직히 말하면, 큰 PR 올리는 게 눈치 보였잖아요. 리뷰어한테 미안하고, 리뷰가 늦어지면 내 작업도 막히고. 그래서 억지로 작게 쪼개다 보면 맥락이 끊기고, 결국 리뷰어가 더 힘들어지는 악순환이 있었죠. 스택 PR은 그 문제를 꽤 우아하게 풀어줘요. 다음 큰 피처 작업할 때 팀에 제안해보세요. 리뷰 문화가 바뀌는 시작점이 될 수 있어요.
