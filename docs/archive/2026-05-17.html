서버 한 대에 10 페타바이트? 랙 하나가 데이터센터가 됩니다

• 키오시아(Kioxia)와 델(Dell)이 2U 서버 한 대에 245.76 TB SSD를 40개 꽂아 총 9.8 PB를 구겨 넣었어요. 랙 하나에 서버 20대를 채우면 무려 196 PB가 됩니다. AI 인프라, 데이터 레이크, 대규모 백업 용도로 설계됐고, AMD EPYC 9005와 400 Gbps NIC 최대 5개를 붙여 병목도 줄였어요.
• 비슷한 용량의 256 TB급 SSD를 마이크론, 샌디스크, SK 하이닉스, 솔리다임도 준비 중이에요. 삼성은 로드맵에 1 PB 단일 드라이브까지 올려두고 있고요. 하드웨어 밀도 경쟁이 본격적으로 시작됐다는 신호예요.
• 다만 QLC NAND는 TLC나 SLC보다 쓰기 내구성이 낮아요. 이 밀도에서 발열 관리와 안정성이 실제로 어떻게 버텨주느냐가 진짜 관건이에요. 스펙 시트의 숫자보다 운영 환경에서의 검증이 훨씬 중요한 시점이에요.

💡 오늘의 인사이트

AI 워크로드 때문에 스토리지 설계를 고민하고 있다면, 이제 '서버 몇 대'가 아니라 '랙 몇 개'로 단위를 바꿔 생각해야 할 것 같아요. 하지만 QLC 기반 고밀도 스토리지는 쓰기 패턴에 민감하니, 도입 전에 실제 워크로드의 쓰기 비율을 꼭 먼저 따져보세요. 스펙에 반해서 질렀다가 내구성에서 발목 잡히는 건 꽤 아픈 경험이거든요.

윈도우 98 위에서 리눅스 커널 6.19가 돌아갑니다. 진짜예요

• WSL9x는 현대 리눅스 커널(6.19)을 윈도우 9x 커널 위에서 협력 실행하는 프로젝트예요. 재부팅 없이 두 운영체제를 동시에 쓸 수 있고, VxD 드라이버, 패치된 리눅스 커널, wsl.com 클라이언트 이렇게 세 조각으로 구성돼 있어요.
• 구현 방식이 정말 기발해요. 윈도우 9x의 인터럽트 디스크립터 테이블이 짧아서 int 0x80을 직접 쓸 수 없거든요. 그래서 일반 보호 오류(GPF) 핸들러를 통해 시스템 콜을 우회해요. 리눅스 커널은 ring 0에서 돌면서 POSIX API 대신 윈도우 9x 커널 API를 직접 호출하고요.
• 빌드 환경도 독특해요. i386-linux-musl 크로스 툴체인과 Open Watcom v2가 필요하고, 코드베이스의 71%가 어셈블리예요. 실험적 프로젝트라 안정성 보장은 없지만, 저수준 시스템 동작 원리를 공부하기엔 교과서보다 훨씬 생생한 자료예요.

💡 오늘의 인사이트

이 프로젝트를 실제로 쓸 일은 없겠지만, 한 번 훑어볼 가치는 충분해요. 인터럽트 핸들러가 왜 존재하는지, 커널이 ring 0에서 뭘 할 수 있는지, 시스템 콜이 어떻게 흘러가는지를 이렇게 극단적인 제약 조건 안에서 보면 개념이 훨씬 선명하게 잡혀요. 평소에 OS 공부가 너무 추상적으로 느껴졌다면, 이 코드가 좋은 자극제가 될 거예요.

WAVE 03 384 pts · 246 comments

8년 만에 Tailwind를 떠났어요. 후회는 없냐고요?

• 한 개발자가 8년간 써온 Tailwind CSS를 버리고 시맨틱 HTML과 바닐라 CSS로 여러 사이트를 옮겼어요. 결론은 '잘 구조화된 바닐라 CSS도 Tailwind만큼 강력하다'는 거예요. 리셋 스타일, 컬러 팔레트, 폰트 스케일 같은 Tailwind의 좋은 아이디어는 CSS 변수와 중첩 선택자로 충분히 재현할 수 있었어요.
• 새로운 CSS 구조는 reset, 컴포넌트, 컬러, 폰트 크기, 유틸리티 클래스, 기본 스타일, 간격, 반응형 순서로 나뉘어요. 컴포넌트마다 고유한 클래스와 전용 CSS 파일을 두고, 다른 컴포넌트의 스타일을 절대 덮어쓰지 않는 규칙을 지켜요. 프레임워크 없이도 일관성을 유지하는 방법을 직접 설계한 거죠.
• 이 결정의 배경엔 기술적 이유 외에도 'Tailwind가 CSS 전문성을 평가절하한다'는 문제의식이 있었어요. 프레임워크에 의존하다 보면 CSS가 실제로 어떻게 동작하는지 모르는 채로 수년이 지나기도 해요. 직접 설계해보는 경험이 장기적으로 더 단단한 실력을 만들어준다는 이야기예요.

💡 오늘의 인사이트

Tailwind를 쓰는 게 잘못된 건 아니에요. 팀 생산성에 분명히 기여하니까요. 다만 한 번쯤은 Tailwind 없이 CSS를 직접 구조화해보는 경험을 해보길 권해요. 사이드 프로젝트 하나 정도에서 시도해보면, 평소에 당연하게 쓰던 것들이 실제로 어떻게 돌아가는지 보이기 시작해요. 그 감각이 쌓이면 Tailwind를 쓸 때도 훨씬 의식적으로 쓰게 되거든요.
