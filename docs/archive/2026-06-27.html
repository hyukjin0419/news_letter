• Sol은 Terminal-Bench 2.1 코딩 워크플로 벤치마크에서 최고 성능을 기록했어요. 더 인상적인 건 사이버보안 벤치마크 ExploitBench에서 경쟁 모델 대비 출력 토큰을 3분의 1만 써도 비슷한 결과를 냈다는 거예요. 토큰 비용이 곧 돈이니까, 이건 꽤 실질적인 차이예요.
• 다만 솔직히 말하면 걱정도 있어요. 사이버보안 능력이 강해진 만큼 악용 가능성도 커졌고, 미국 정부와 협조해서 출시 시점을 조율하고 있다는 점은 개발자 입장에서 접근 시기가 불투명하다는 뜻이기도 해요.

💡 오늘의 인사이트

Terra가 GPT-5.5 수준의 성능을 절반 가격에 제공한다면, 지금 GPT-5.5를 쓰고 있는 프로젝트라면 전환 검토를 미리 해두는 게 좋아요. 특히 API 호출량이 많은 서비스라면 비용 차이가 꽤 크게 나올 수 있거든요. 정식 출시 전에 벤치마크 수치를 자기 업무 케이스에 맞게 직접 테스트해보는 걸 추천해요.

오픈소스 LLM이 클로즈드 모델을 따라잡는다는 말, 어디까지 믿어야 할까요

• 단일 벤치마크만 보면 오픈소스 LLM이 2026년 12월쯤 클로즈드 모델과 격차를 완전히 좁힌다는 예측이 나와요. 그런데 Artificial Analysis Intelligence Index의 18개 벤치마크를 종합해서 보면 얘기가 달라져요. 평균 격차는 약 5개월 수준에서 거의 그대로예요.
• 그나마 희망적인 건 코딩 벤치마크예요. 예전엔 15개월이나 뒤처졌는데 지금은 1~2개월 차이로 줄었어요. 코드 작성 보조 도구로 오픈소스 모델을 쓰는 팀이라면 이 흐름은 직접 체감할 수 있는 변화예요.
• 핵심 교훈은 이거예요. 어떤 벤치마크를 쓰느냐에 따라 결론이 완전히 달라진다는 것. 모델 선택 결정을 내릴 때 단 하나의 지표만 보고 판단하면 실제 업무에서 실망할 수 있어요.

💡 오늘의 인사이트

오픈소스냐 클로즈드냐 논쟁보다 더 중요한 건 내 팀의 실제 작업에 어떤 모델이 잘 맞는지예요. 벤치마크는 참고 자료일 뿐이고, 직접 우리 데이터로 돌려보는 게 가장 정직한 평가예요. 비용, 레이턴시, 정확도 세 가지를 동시에 보는 내부 평가 기준을 하나쯤 만들어두면 나중에 두고두고 써먹을 수 있어요.

WAVE 03 231 pts · 136 comments

AI가 만든 코드를 안전하게 실행하고 싶다면, 이제 선택지가 생겼어요

• AWS Lambda가 MicroVMs를 내놨어요. 사용자나 AI가 생성한 코드를 격리된 환경에서 실행할 수 있는 서버리스 컴퓨팅 기본 단위예요. 내부적으로는 매달 15조 번 이상의 Lambda 실행을 담당하는 Firecracker 기술 위에 만들어졌어요. 신뢰할 수 없는 코드를 돌려야 하는 상황에서 VM 수준의 격리를 제공하면서도 인프라 관리는 없애버렸어요.
• 스펙도 꽤 넉넉해요. MicroVM 하나당 최대 16 vCPU, 32GB 메모리, 32GB 디스크를 쓸 수 있고, 사용하지 않을 때는 API 호출이나 자동 정책으로 일시정지해서 유휴 비용을 줄일 수 있어요. 현재 미국, 유럽, 도쿄 리전에서 ARM64 아키텍처로 제공돼요.
• AI 에이전트가 코드를 직접 실행하는 워크플로를 만들고 있다면 이건 꽤 중요한 소식이에요. 격리 없이 AI 생성 코드를 실행하는 건 보안 사고를 기다리는 것과 같거든요. Docker와 Amazon Linux 2023을 지원하니까 기존 컨테이너 기반 워크플로와 연결하기도 어렵지 않아요.

💡 오늘의 인사이트

AI 코드 실행 환경을 직접 구축하려면 격리, 상태 관리, 비용 세 가지를 동시에 해결해야 해서 생각보다 손이 많이 가요. MicroVMs는 그 세 가지를 묶어서 관리형으로 제공하는 거라, 지금 AI 에이전트 관련 기능을 개발 중이라면 직접 샌드박스를 만들기 전에 이 옵션을 먼저 살펴보는 게 시간을 아끼는 길일 수 있어요.
