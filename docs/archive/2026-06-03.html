GitHub Copilot에 새 엔진이 달렸어요. 토큰은 60% 줄고, 성능은 올랐다고요?

• Microsoft가 MAI-Code-1-Flash를 공개했어요. GitHub Copilot에 바로 탑재되는 코딩 전용 모델인데, Claude Haiku 4.5보다 코딩 벤치마크 전 항목에서 앞서고, SWE-Bench Pro에서는 무려 16점 차이가 났어요. 숫자만 보면 꽤 인상적이죠.
• 진짜 눈에 띄는 건 효율이에요. 같은 문제를 풀 때 토큰을 최대 60% 덜 쓴다는 건, 응답이 그만큼 빠르고 비용도 줄어든다는 뜻이에요. 간단한 질문엔 짧게, 복잡한 문제엔 깊게 답하는 adaptive solution length control 덕분이에요.
• 별도 설정 없이 Visual Studio Code의 GitHub Copilot 개인 사용자에게 순차적으로 배포 중이에요. 벤치마크용으로 튜닝한 게 아니라 실제 개발 환경 데이터로 학습했다는 점도 믿음이 가는 부분이에요.

GPU VRAM을 스왑 메모리로 쓴다고요? 메모리 부족에 시달리는 리눅스 개발자라면 주목해요

• nbd-vram은 NVIDIA GPU의 VRAM을 리눅스 스왑 공간으로 쓸 수 있게 해주는 데몬이에요. NBD(Network Block Device) 프로토콜을 유닉스 소켓으로 연결하는 방식이라, 커널 모듈 없이 일반 GeForce GPU에서도 동작해요. 커널이나 드라이버를 업데이트해도 다시 빌드할 필요가 없어요.
• 메모리 우선순위는 RAM, VRAM(PCIe 경유), zram(CPU 압축), SSD 순이에요. RTX 3070 랩톱 기준으로 측정한 순차 처리 속도는 약 1.3 GB/s였고, 이 셋을 함께 쓰면 사용 가능한 메모리가 세 배 가까이 늘어요.
• 메모리가 부족할 때 512 MiB 단위로 조금씩 줄여가는 방식이라 GPU 작업과 충돌을 어느 정도 피할 수 있어요. 배터리로 전환되거나 AC가 빠지면 서비스를 멈추는 전원 관리 옵션도 있어요.

💡 오늘의 인사이트

VRAM은 전원이 끊기면 데이터가 날아가는 휘발성 저장소예요. 스왑으로 쓴다는 건 그 위험을 감수한다는 뜻이죠. 그래서 GPU 집중 작업 중에 스왑까지 VRAM에 몰리면 성능이 급격히 떨어질 수 있어요. 메모리가 모자라 SSD 스왑이 터지는 상황이 잦은 개발 머신이라면 시도해볼 만하지만, 중요한 작업 중엔 전원 관리 설정을 꼭 확인하고 쓰세요.

BYD 부품을 CT로 찍었더니, 제조업의 민낯이 보였어요

• BYD 자동차 부품을 CT 스캔으로 분석한 이번 콘텐츠는 사실 플라스틱 병의 역사와 맞닿아 있어요. 1826년 에비앙의 도기 항아리부터 1899년 코카콜라의 유리병, 1975년에 출시됐다가 2년도 안 돼 사라진 아크릴로니트릴 공중합체 병까지, 소재 선택 하나에 엄청난 R&D가 들어갔어요.
• 지금 우리가 쓰는 대부분의 병은 PET 플라스틱이에요. 가볍고 성형하기 쉬운 대신, 색깔 있는 유리병처럼 재활용 인프라가 따라가지 못하는 소재들은 결국 매립지로 가요. 엄청난 공학적 노력이 일회용품에 쏟아지는 아이러니예요.
• CT 스캔이라는 도구로 완성품 내부를 들여다보는 방식은, 소프트웨어로 치면 블랙박스 시스템을 역분석하는 것과 비슷해요. 어떤 결정이 어떤 구조를 만들었는지, 결과물을 보면 설계 의도가 보이기도 하죠.

💡 오늘의 인사이트

우리가 매일 쓰는 물건 하나에도 수십 년의 실패와 개선이 쌓여 있어요. 소프트웨어도 마찬가지예요. 지금 당연하게 쓰는 라이브러리나 패턴 뒤에도 누군가의 긴 시행착오가 있어요. 가끔은 내가 쓰는 도구의 역사를 찾아보는 것, 꽤 재밌는 개발 공부가 돼요.
