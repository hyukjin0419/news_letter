우주정거장에서 공기가 새고 있다면, 당신의 온콜 대응은 충분한가요?

• 국제우주정거장(ISS) 러시아 구역 Zvezda 모듈에서 공기 누출 두 건이 발견됐어요. 우주비행사 다섯 명은 수리가 진행되는 동안 각자의 우주선 안으로 대피했고, 수리팀은 데이터를 재검토한 뒤 작업을 재개했죠.
• 러시아 측은 누출 하나는 이미 막았고, 승무원과 시스템 모두 위험하지 않다고 밝혔어요. 하지만 Zvezda 모듈은 이미 오래전부터 균열과 누출 이력이 있었던 곳이에요.
• 수리 중 측정값이 예상과 다르자 즉시 작업을 멈추고 데이터를 다시 확인했어요. 서두르지 않고 측정 결과를 신뢰하는 태도가 결국 승무원을 지켰죠.

💡 오늘의 인사이트

장애 대응 매뉴얼이 있어도 막상 새벽 세 시에 알림이 오면 손이 먼저 움직이죠. 우주정거장 수리팀도 데이터가 이상하면 멈추고 다시 확인했어요. 우리 팀도 인시던트 중에 '일단 뭔가 해야 한다'는 압박보다 '지금 보이는 지표가 진짜인지' 먼저 묻는 습관을 만들어 두면 어떨까요? 롤백이든 핫픽스든, 근거 없이 빠른 것보다 느려도 정확한 게 훨씬 낫거든요.

WAVE 02 277 pts · 72 comments

크론잡, 워커, 큐 없이 PostgreSQL 안에서 워크플로를 돌릴 수 있어요

• 마이크로소프트가 pg_durable이라는 PostgreSQL 확장을 오픈소스로 공개했어요. 긴 작업을 SQL 함수로 정의하면 단계마다 자동으로 체크포인트를 찍고, 서버가 꺼졌다 켜져도 멈춘 지점부터 다시 이어서 실행해요.
• 외부 인프라가 전혀 필요 없어요. cron, 별도 워커 프로세스, 메시지 큐 없이 PostgreSQL 백그라운드 워커 하나로 전부 돌아가요. ~>, |=> 같은 SQL 연산자로 순차 실행과 병렬 실행을 조합할 수 있고, HTTP 호출도 SQL 안에서 가능해요.
• 다만 설치에 슈퍼유저 권한이 필요하고, 관리형 PostgreSQL 환경에서는 제약이 있을 수 있어요. 현재 미리보기 상태라 프로덕션 도입 전에 충분한 검증이 필요하고, 복잡한 애플리케이션 로직은 SQL 함수로 감싸야 한다는 점도 고려해야 해요.

💡 오늘의 인사이트

배치 작업 하나 추가할 때마다 스케줄러 설정하고, 워커 서버 띄우고, 큐 연결하고... 이 과정이 본 작업보다 오래 걸릴 때가 있죠. pg_durable은 그 피로감을 꽤 많이 줄여줄 수 있어요. 특히 데이터가 이미 PostgreSQL에 있는데 굳이 외부 시스템을 거쳐야 하는 워크플로라면 한번 살펴볼 만해요. 아직 미리보기니까 당장 프로덕션에 올리기보다, 사이드 프로젝트나 내부 도구에서 먼저 써보는 걸 추천해요.

WAVE 03 231 pts · 77 comments

1GB도 안 되는 AI 모델, 이제 노트북에서 직접 돌릴 수 있어요

• 구글이 Gemma 4 모델의 QAT(양자화 인식 훈련) 버전을 공개했어요. 일반적인 사후 양자화와 달리, 훈련 과정에서 양자화를 미리 시뮬레이션해서 품질 손실을 훨씬 줄였어요.
• 모바일 특화 양자화 방식을 적용하면 Gemma 4 E2B 텍스트 모델의 메모리 사용량이 1GB 아래로 내려와요. 텍스트, 오디오, 비전 중 필요한 기능만 골라서 올리면 메모리를 더 아낄 수 있어요.
• llama.cpp, Ollama, vLLM, LM Studio 등 이미 익숙한 도구들과 바로 연동돼요. Hugging Face에서 GGUF나 압축 텐서 형식으로 받을 수 있어요.

💡 오늘의 인사이트

온디바이스 AI가 점점 현실적인 선택지가 되고 있어요. API 비용 걱정 없이, 인터넷 연결 없이, 민감한 데이터를 외부로 보내지 않고 모델을 돌릴 수 있다는 건 생각보다 큰 장점이에요. 지금 당장 서비스에 쓸 게 아니더라도, 로컬에서 Ollama로 한번 돌려보세요. 개발 중에 빠르게 프로토타입 테스트하는 용도로만 써도 충분히 값어치 있거든요.
