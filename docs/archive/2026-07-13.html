Math.tanh 한 줄로 OS가 들통난다고요?

• Chrome 148부터 Math.tanh가 브라우저 내장 라이브러리 대신 운영체제의 수학 라이브러리(glibc, libsystem_m, UCRT)를 직접 호출하게 됐어요. 덕분에 Linux, macOS, Windows마다 비트 단위로 미묘하게 다른 결과값이 나오고, 이 차이만으로 실제 OS를 특정할 수 있게 됐죠.
• 문제는 User-Agent를 아무리 바꿔도 소용없다는 거예요. Math.tanh 결과는 브라우저가 아니라 OS가 만들어내는 값이거든요. 안티봇 시스템 입장에서는 꽤 반가운 핑거프린팅 벡터가 생긴 셈이에요. 브라우저 자동화 도구를 운영 중이라면 이 부분을 반드시 챙겨야 해요.
• Math.sin, Math.cos, Math.exp 같은 함수들은 V8이 llvm-libc를 정적 링크해서 쓰기 때문에 OS와 무관하게 동일한 결과가 나와요. 이번에 유출된 건 Math.tanh와 Web Audio API의 컴프레서 노드 등 일부 함수에 국한돼요.

💡 오늘의 인사이트

IEEE 754가 초월함수의 정확한 반올림을 보장하지 않는다는 사실, 알고 계셨나요? 각 OS 벤더가 서로 다른 근사 알고리즘을 쓸 수 있다는 게 이번 이슈의 근본 원인이에요. Playwright나 Puppeteer로 스크래퍼를 운영 중이라면, 수학 함수 결과값을 후킹하거나 정규화하는 레이어를 고려해볼 시점이에요. 작은 숫자 하나가 신원을 드러낼 수 있다는 게 꽤 섬뜩하죠.

80년대 컴퓨터, 브라우저에서 그냥 켜진다

• Tiny Emus는 ZX Spectrum, Commodore 64, Amstrad CPC 등 15개 이상의 레트로 컴퓨터를 웹에서 바로 실행할 수 있는 에뮬레이터 모음이에요. 설치 없이 브라우저만 있으면 돼요.
• 게임만 있는 게 아니에요. FORTH, BASIC, ASMDEV 같은 개발 도구도 포함돼 있어서, 8비트 시대의 프로그래밍 환경을 직접 체험해볼 수 있어요. Amstrad CPC에서는 CP/M 2.2도 돌아가요.
• Visual 6502, Visual Z80 같은 트랜지스터 수준 시뮬레이터도 포함돼 있어요. CPU가 실제로 어떻게 동작하는지 눈으로 확인하고 싶은 분께는 꽤 색다른 경험이 될 거예요.

💡 오늘의 인사이트

레트로 에뮬레이터가 단순한 향수 이상의 의미를 가질 때가 있어요. 제약이 극단적인 환경에서 개발자들이 어떻게 문제를 풀었는지 보다 보면, 요즘 우리가 당연하게 쓰는 추상화 레이어들이 얼마나 대단한 발명인지 새삼 느끼게 되거든요. 가볍게 C64 BASIC 한 줄 쳐보는 것만으로도 꽤 좋은 머리 환기가 돼요.

AI 코딩 도구, 첫 글자 입력 전에 이미 3만 3천 토큰을 썼다

• Claude Code는 사용자 입력이 한 글자도 들어오기 전에 시스템 프롬프트, 툴 스키마, 스캐폴딩만으로 33,000토큰을 소비해요. OpenCode는 같은 조건에서 7,000토큰이에요. 프로덕션 환경에서 72KB짜리 instruction 파일과 MCP 서버까지 붙이면 첫 요청 전에 이미 75,000~85,000토큰이 나가요.
• 캐시 효율도 차이가 커요. Claude Code는 세션 중간에 캐시 토큰을 다시 쓰는 일이 잦아서 OpenCode 대비 최대 54배 많은 캐시 토큰을 발생시켜요. 캐시 토큰은 일반 토큰보다 비용이 낮지만, 이 정도 격차면 청구서가 예상치 못하게 튀어오를 수 있어요.
• 서브에이전트를 쓸 때는 더 조심해야 해요. 직접 실행 시 121,000토큰이던 작업이 서브에이전트 두 개로 팬아웃되면 513,000토큰으로 4배 넘게 불어났어요. 멀티스텝 툴 콜 배치 효율은 Claude Code가 더 좋지만, 비용 구조는 반드시 직접 측정해봐야 해요.

💡 오늘의 인사이트

AI 코딩 도구를 팀에 도입할 때 기능 비교만큼 중요한 게 토큰 소비 구조 파악이에요. HTTP 프록시를 API와 하네스 사이에 끼워서 실제 토큰 흐름을 로깅해보는 방법, 생각보다 어렵지 않아요. 비용이 예상보다 많이 나온다면 instruction 파일 크기부터 줄여보세요. 수만 토큰짜리 맥락을 매 요청마다 밀어 넣는 것보다, 필요한 정보만 담은 작은 프롬프트가 지갑과 성능 모두에 나을 때가 많아요.
