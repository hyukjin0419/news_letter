27B짜리 AI가 폰에서 돌아간다고요? 진짜입니다

• PrismML이 공개한 Bonsai 27B는 Qwen3.6 27B를 기반으로 극단적인 양자화를 적용한 멀티모달 모델이에요. 1비트 변형은 3.9GB로 줄어들어 iPhone 17 Pro에서 바로 실행되고, 3항(ternary) 변형은 5.9GB로 원본 성능의 95%를 유지해요.
• 수학과 코딩 능력은 양자화 후에도 거의 손상이 없고, 262K 토큰 컨텍스트 윈도우에 툴 콜링, 비전 태스크, 에이전틱 워크플로까지 지원해요. GB당 지능 밀도가 풀 프리시전 대비 10배 높다는 게 핵심이에요.
• 라이선스는 Apache 2.0이고, 개발자 프리뷰 API도 한시적으로 무료로 열려 있어요. 다만 API 제공 기간이 정해져 있어서 장기 프로덕션 의존은 아직 조심해야 해요.

💡 오늘의 인사이트

온디바이스 AI가 드디어 '쓸 만한 크기'에 도달했다는 신호예요. 서버 없이 사용자 기기에서 추론이 돌아간다는 건, 개인정보 처리 방식과 인프라 비용 설계를 처음부터 다시 생각해볼 수 있다는 뜻이기도 하죠. 지금 당장 프로덕션에 쓰기보다는, 사이드 프로젝트나 내부 도구에 한번 얹어보면서 감을 잡아두는 게 좋을 것 같아요.

Dependabot이 이제 3일을 기다려줘요. 나쁜 패키지가 들어오기 전에

• GitHub의 Dependabot이 버전 업데이트 PR을 열기 전에 기본 3일의 쿨다운을 두기 시작했어요. 새 릴리스가 나왔을 때 커뮤니티가 문제를 발견할 시간을 벌어주는 거예요. 공급망 공격처럼 배포 직후에 문제가 터지는 경우를 막기 위한 조치예요.
• 보안 업데이트는 쿨다운 없이 즉시 PR이 열려요. 중요한 취약점 패치가 늦어지는 일은 없으니 걱정 안 해도 돼요. GitHub Enterprise Server 3.23부터 적용돼요.
• 쿨다운 기간은 .github/dependabot.yml의 cooldown 옵션으로 직접 조정하거나 끌 수 있어요. 팀 배포 주기에 맞게 커스터마이징이 가능해요.

💡 오늘의 인사이트

Dependabot PR이 열리자마자 머지하는 팀이라면 이 변화가 꽤 반가울 거예요. 사실 패키지 하나 잘못 올라와서 프로덕션 터진 경험, 다들 한 번쯤은 있잖아요. 3일이라는 시간이 작아 보여도, 오픈소스 생태계가 문제를 잡아내기엔 충분한 경우가 많아요. 지금 바로 팀 dependabot.yml 설정 한번 들여다보는 걸 추천해요.

AI가 코드를 대신 짜줄수록, 팀이 무너지는 속도도 빨라진다는 이야기

• AI 에이전트는 개발자 한 명의 속도를 확실히 올려줘요. 그런데 대형 소프트웨어 프로젝트의 진짜 병목은 개인의 코딩 속도가 아니라 팀 간 조율 능력이에요. AI가 조율 없이 독립적인 변경을 가능하게 만들수록, 팀 전체의 시스템 이해는 조용히 무너질 수 있어요.
• 코드 리뷰나 협업 과정의 '마찰'은 불편하지만, 사실 팀이 아키텍처 언어를 공유하게 만드는 장치였어요. AI 에이전트가 이 마찰을 없애버리면, 코드는 컴파일되고 테스트도 통과하지만 설계 원칙은 조각나요.
• 바벨탑 이야기와 달리, AI 시대엔 공통 언어가 사라져도 탑은 계속 올라가요. 문제가 눈에 안 보이는 게 오히려 더 위험한 이유예요.

💡 오늘의 인사이트

AI 도구를 팀에 도입할 때 '속도'만 보면 절반만 본 거예요. 지금 팀에서 AI가 만든 PR을 리뷰할 때, 작성자가 그 코드의 맥락을 설명할 수 있는지 한번 확인해보세요. 설명 못 하는 코드가 쌓이기 시작하면, 그게 기술 부채의 새로운 얼굴이에요. AI를 잘 쓰는 팀은 속도를 얻으면서도 공유된 이해를 지키는 방법을 함께 고민하는 팀이라고 생각해요.
