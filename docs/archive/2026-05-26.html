AI 어시스턴트가 내 파일을 몰래 빼돌린다고요? Microsoft Copilot 보안 구멍 이야기

• Microsoft Copilot Cowork에서 간접 프롬프트 인젝션(Indirect Prompt Injection) 취약점이 발견됐어요. 사용자가 온라인에서 내려받은 스킬 파일에 악성 프롬프트를 심어두면, Copilot이 그걸 그대로 실행해버리거든요. 81줄짜리 스킬 파일 안에 단 5줄만 넣어도 공격이 성공했다는 게 소름 돋는 부분이에요.
• 더 무서운 건 Teams와 Outlook으로 보내는 메시지는 사람의 승인 없이 자동으로 발송된다는 점이에요. 공격자는 악성 HTML img 태그를 메시지에 심어서, SharePoint나 OneDrive의 사전 인증된 파일 다운로드 링크를 자기 서버로 빼낼 수 있어요. 개인정보나 재무 데이터가 타깃이 될 수 있죠.
• 예약 실행 태스크(Scheduled Tasks)가 설정돼 있으면 위험이 훨씬 커져요. 사용자가 아무것도 안 해도 주기적으로 공격이 반복되거든요. 게다가 관리자도 어떤 스킬이 로드됐는지 들여다보기 어렵다는 게 현실이에요.

💡 오늘의 인사이트

AI 어시스턴트 도입이 빨라질수록, '이 도구가 어디까지 자동으로 움직이는지'를 팀 차원에서 먼저 확인해야 해요. 특히 외부에서 가져온 스킬 파일이나 플러그인은 코드 리뷰하듯 한 번은 들여다보는 습관이 필요해요. 편리함과 보안은 항상 트레이드오프라는 걸, 이번 사례가 다시 한번 일깨워주네요.

WAVE 02 118 pts · 61 comments

노르웨이 국립도서관이 LLM을 직접 만드는 이유, 알고 보면 우리 얘기예요

• 노르웨이 국립도서관이 자국어 LLM을 직접 개발하고 있어요. 이유는 단순해요. 노르웨이어를 제대로 다루는 상용 모델이 없거든요. 60PB에 달하는 노르웨이 문화 콘텐츠 디지털 아카이브를 보유하고 있고, 저작권 있는 신문 기사도 학습에 쓸 수 있는 법적 권리까지 갖고 있어요. 이런 조건이 갖춰지자 문화부가 직접 개발을 맡겼죠.
• 흥미로운 건 병목이 컴퓨팅 파워가 아니라는 점이에요. Nvidia DGX H200과 HPE Cray 슈퍼컴퓨터(GPU 448개)는 이미 있어요. 진짜 문제는 보존용 아카이브 스토리지와 AI 학습 파이프라인 스토리지가 최적화 목표 자체가 달라서, 2PB 규모의 데이터를 두 시스템 사이에서 깔끔하게 옮기는 게 너무 어렵다는 거예요.
• 데이터 품질 정제 파이프라인과 노르웨이어 방언별 평가 도구 개발도 현재 진행 중인 과제예요. 거버넌스, 즉 이 LLM에 누가 어떻게 접근할 수 있는지에 대한 정책도 아직 정해지지 않았고요. 기술보다 데이터와 조직 문제가 더 느리게 풀린다는 게 현실이에요.

💡 오늘의 인사이트

LLM 프로젝트를 시작하면 GPU 확보에 온 에너지를 쏟게 되는데, 정작 발목을 잡는 건 데이터 파이프라인 처리량이나 스토리지 시스템 간 호환성인 경우가 많아요. 노르웨이 사례처럼 '데이터를 어떻게 깨끗하게 흘려보낼 것인가'를 컴퓨팅 계획만큼 일찍, 꼼꼼하게 설계해두는 게 결국 시간을 아끼는 길이에요.

Exit IP VPN 서버 13대, 조용히 패치 완료됐어요

• 9개국에 분산된 Exit IP VPN 서버 13대에 새로운 보안 완화 조치가 적용됐어요. 호주, 캐나다, 독일, 핀란드, 프랑스, 아일랜드, 노르웨이, 스웨덴, 미국이 대상 지역이에요.
• 사용 중인 프로토콜은 WireGuard예요. 기존 OpenVPN이나 IPSec보다 코드베이스가 훨씬 작아서 공격 표면 자체가 좁다는 게 장점이지만, 그렇다고 완전히 안심할 수는 없다는 걸 이번 패치가 보여주죠.
• 이번 공지에서 구체적인 취약점 내용이나 위험 수준은 공개되지 않았어요. VPN 인프라를 운영하는 팀이라면 자체 서버 현황을 한 번 점검해보는 게 좋을 것 같아요.

💡 오늘의 인사이트

VPN 패치는 조용히 배포되고 조용히 넘어가는 경우가 많아요. 하지만 Exit IP 서버는 트래픽이 실제로 나가는 지점이라 보안 설정 변경이 서비스에 영향을 줄 수 있어요. 인프라 변경 이력을 팀 내에서 가시화해두는 것, 생각보다 중요한 습관이에요.
