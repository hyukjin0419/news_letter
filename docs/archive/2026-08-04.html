WAVE 01 272 pts · 115 comments

AI를 잘 쓰는 사람과 못 쓰는 사람의 차이, 결국 이거였어요

• LLM은 비전문가도 '그럭저럭 쓸 만한' 결과물을 낼 수 있게 해줘요. 하지만 ChatGPT로 수학 난제를 푼 테런스 타오처럼, 진짜 전문가는 모델이 틀렸을 때 바로 알아채고 더 날카롭게 방향을 잡아줄 수 있죠.
• 좋은 Prompting의 핵심은 '멋진 문장'이 아니에요. 내가 원하는 결과가 뭔지 구체적으로 알고, 모델 출력을 평가할 수 있는 능력이에요. 도메인 지식이 곧 프롬프트 실력이에요.
• 특히 우리 팀 코드베이스처럼 구체적인 맥락을 아는 것이 일반적인 원칙보다 훨씬 강력해요. 모델에게 '우리 팀 컨벤션'을 설명할 수 있는 사람이 결국 AI를 가장 잘 쓰는 사람이에요.

💡 오늘의 인사이트

AI가 내 자리를 빼앗는다는 걱정, 사실 반은 맞고 반은 틀려요. 내 전문성을 AI한테 잘 전달하는 능력, 그게 앞으로 가장 중요한 기술이 될 것 같아요. 지금 하는 공부가 절대 헛되지 않아요.

WAVE 02 383 pts · 672 comments

AI가 수학 난제 10개를 2,000달러에 풀었어요. 우리가 생각해볼 것들

• OpenAI 내부 모델 Astra가 고차원 기하학, 코딩 이론, 양자 복잡도 등 수십 년 묵은 수학 난제 10개를 해결했어요. 계산 비용은 Sol API 기준 약 2,000달러였고, 증명은 Lean으로 형식화됐어요.
• 흥미로운 건 AI가 에르되시 단위거리 추측을 반증한 방식이 이후 수학자들의 후속 연구를 자극했다는 점이에요. AI가 결론을 내린 게 아니라, 새로운 질문의 출발점이 된 거죠.
• OpenAI는 10만 명의 연구자에게 ChatGPT 무료 접근권을 줬고, AI가 기여한 부분을 솔직하게 표기하는 기준을 강조했어요. 기여 출처를 어떻게 표기할지는 우리 업계도 곧 진지하게 고민해야 할 문제예요.

💡 오늘의 인사이트

2,000달러짜리 토큰으로 수학 난제가 풀리는 시대가 됐어요. 그렇다고 수학자가 필요 없어진 게 아니듯, 우리도 마찬가지예요. AI가 만든 결과물을 원고로 다듬고 검증한 건 결국 사람이었으니까요. 도구가 강력해질수록 그 도구를 판단하는 눈이 더 중요해져요.

WAVE 03 465 pts · 171 comments

개발 도구가 오픈소스여야 하는 이유, AI 시대엔 더 분명해졌어요

• AI 에이전트 덕분에 소프트웨어 커스터마이징의 비용이 확 낮아졌어요. 예전엔 포크 뜨고 직접 유지보수하는 게 너무 힘들었는데, 이제 에이전트가 upstream 변경사항을 자동으로 리베이스해줘요.
• Shelley, Pi, Codex 같은 오픈소스 에이전트는 소스 코드 전체를 바꿀 수 있어요. 반면 Claude Code 같은 클로즈드 소스는 미리 정해진 훅 안에서만 커스터마이징이 가능해요. 내가 원하는 대로 바꾸려면 결국 오픈소스가 답이에요.
• AI 모델은 반복적이고 정형화된 작업엔 탁월하지만, 아키텍처 결정이나 예상 밖의 엣지 케이스엔 아직 약해요. 커스터마이징이 자유로운 도구일수록 이 빈틈을 우리가 직접 채울 수 있어요.

💡 오늘의 인사이트

편하다고 클로즈드 소스 도구만 쓰다 보면, 어느 순간 내가 도구에 맞춰 일하고 있는 걸 발견하게 돼요. 지금 쓰는 개발 도구가 오픈소스인지 한 번 확인해보는 것도 나쁘지 않아요. 내 워크플로우의 주도권은 내가 쥐고 있어야 하니까요.
